# Rôles

**Qui fait quoi dans la squad ?**  
Une squad (équipe produit autonome) est une petite équipe pluridisciplinaire. Imaginez un commando où chacun a sa spécialité mais où tout le monde partage la même mission.

Voici les profils avec qui vous allez passer vos journées :

**Le product manager (PM) : Le chef d'orchestre**  
C'est le garde du corps de l'équipe et le garant du POURQUOI.

- Son but : Faire en sorte que le produit réussisse (soit utilisé et viable).  
- La réalité du métier :  
  - Il représente la voix des utilisateurs (souvent avec le designer) et celle du business.  
  - Il écrit des spécifications, mais jamais seul : il le fait en collaboration avec les développeurs pour trouver la meilleure solution technique.  
  - Ce n'est pas le chef hiérarchique, c'est un facilitateur. C'est le couteau suisse de l'équipe : s'il manque une info, il va la chercher. S'il faut calmer un stakeholder énervé, il y va. S'il y a un blocage, il le lève.  
  - Il passe beaucoup de temps à communiquer pour vendre le travail de l'équipe au reste de l'entreprise.

**Le product designer : L'avocat de l'utilisateur**  
Attention, ce n'est pas juste "celui qui fait les jolies maquettes". Ils détestent qu'on réduise leur métier à ça.

- Son but : Comprendre comment le produit s'insère dans la vie réelle des gens.  
- La réalité du métier :  
  - Il étudie le contexte : L'utilisateur est-il pressé ? Est-il dans le métro ? (Ex: Sur Leboncoin, on y pense ponctuellement, on veut aller vite).  
  - Il conçoit le parcours (UX) et l'interface (UI).  
  - Il s'assure que la solution technique répond vraiment au besoin humain identifié.

**Les builders : Développeurs et data scientists**  
C'est vous. Que vous fassiez du Java, du React (Frontend), du Python (Backend) ou du ML (Data Science), vous êtes les créateurs de valeur.

- Votre but : Transformer un besoin abstrait en solution concrète et fiable.  
- La réalité du métier :  
  - Vous êtes les maîtres du COMMENT.  
  - Le PM vous apporte un problème ("Les gens ne cliquent pas"), vous apportez la solution technique ("On va changer l'algo de tri").  
  - Vous êtes responsables de la faisabilité et de la maintenabilité de ce que vous construisez.

**Le QA (Quality Assurance) / Testeur : Le filet de sécurité**  
C'est l'ingénieur qui cherche à casser ce que vous avez construit pour être sûr que ça tienne la route.

- Son but : Industrialiser la qualité et éviter les régressions (bugs).  
- La réalité du métier :  
  - Il automatise les tests pour gagner du temps.  
  - Attention : La présence d'un QA ne vous dispense pas de tester ! La qualité est une responsabilité collective :  
    - Le designer vérifie que l'interface correspond à la maquette (design review).  
    - Le dev/DS teste son code (tests unitaires).  
    - Le PM vérifie que la fonctionnalité est utile (acceptance test).  
    - Le QA vérifie que tout le système tient ensemble.

**Les facilitateurs techniques (rôles de support)**  
Vous les croiserez peut-être moins souvent au quotidien, mais ils sont vitaux :

- L'engineering manager (EM) : C'est souvent votre manager hiérarchique. Il ne gère pas le produit, il gère les gens (carrière, bien-être) et les process (comment on s'organise pour coder mieux).  
- L'architecte : Il définit les grandes lignes techniques (les fondations) pour s'assurer que toutes les équipes ne partent pas dans tous les sens.
